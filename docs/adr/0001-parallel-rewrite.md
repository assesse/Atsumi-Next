# ADR-0001: Classic 보존과 병행 재작성

- 상태: 승인
- 결정일: 2026-08-12

## 맥락

Classic은 실제 사용자 요구를 검증했지만 UI 상태, JSON, SQLite와 파일 시스템의 책임이 겹쳐 있다. 전면 교체 중 현재 프로그램을 잃으면 검증된 동작과 문제 해결 지식도 잃는다.

## 결정

- Classic을 tag로 보존한다.
- Atsumi Next는 별도 branch와 하위 workspace에서 개발한다.
- Classic은 참고 구현과 fixture 생성 도구로 사용한다.
- Next는 Classic 데이터 원본을 직접 수정하지 않는다.
- 전환 전 일정 기간 두 버전을 병행한다.

## 결과

- 새 구조를 자유롭게 설계할 수 있다.
- 기능 동등성 비교가 가능하다.
- 두 구현을 유지하는 기간이 생기지만 rollback 위험이 낮아진다.
